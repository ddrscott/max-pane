# ADR 0031 — Paste history is what terminals pasted and copied, never the clipboard

**Status:** Accepted · 2026-09-21
**Decides:** what ⇧⌘H's list is made of; what is never in it; what is kept of
each kind of paste; and where each of those is enforced.
**Evidence:** the work item [`docs/work/paste-history.md`](../work/paste-history.md);
`crates/laned-core/src/clips.rs`, migration `0016_clip_history.sql` and
`tests/clips.rs`; `TerminalPaneController.send(pasted:…record:)`;
`PasteHistoryPicker.swift`; `PasteHistoryTests.swift`.

## The facts

1. iTerm's ⇧⌘H recalls recent pastes, and the owner wants to stop needing
   iTerm. The case is small: copy a path, copy something else, want the path.
2. A clipboard holds passwords. A clipboard *manager* is, mechanically, a
   keylogger for everything a person copies anywhere, and it becomes one by
   polling `NSPasteboard.general`.
3. Password managers mark what they copy (nspasteboard.org):
   `org.nspasteboard.ConcealedType`, `…TransientType`, `…AutoGeneratedType`.
   The mark is on the pasteboard only while that copy is; it has to be read
   with the content or not at all.
4. Every paste into a terminal ends in one method, `send(pasted:)` (ADR-0026,
   0027, 0029, 0030), and a paste cancelled in the sheet never reaches it.
   A program's copy lands in one method, `commitProgramCopy` (ADR-0028).
   ⌘C and copy-on-select are the emulator's and tell nobody.
5. A private lane writes nothing to the ledger (ADR-0016), and the ledger
   already answers "is this pane's lane private" for visits.

## Decision

**Max Pane never polls or observes the system clipboard.** A row exists only
because a terminal pane of this app *sent* those bytes to a prompt or *copied*
that text out. What was copied in Safari and pasted into Mail is never seen.
This is the line between a paste history and a keylogger, and it is why the
list cannot show "the thing I copied a minute ago and never pasted here".

**What is recorded is what was sent, as text**, taken at `send(pasted:)`:

| paste | kept |
|---|---|
| ⌘V, middle click, a drop of text | the text after tidying, without its trailing line ending |
| ⌥⌘V | the text as copied |
| through the sheet | what the sheet sent (one-lined, tabs as spaces); **cancelled: nothing** |
| copied files, dropped files | the quoted paths |
| a picture | the path it became, on this Mac or on the server |
| Paste Escaped, as Base64, Base64-Decoded | the bytes sent, not the clipboard |
| Paste File as Base64… | **nothing**: it is a file's contents, the file is still there, and a key in base64 has no shape to catch |
| Paste Slowly | the whole text when it starts, even if Esc stops it part way |
| ↩ in the picker | the entry again, which moves it to the top |

Sent rather than copied because ↩ in the picker pastes a row **untidied**
(confirm sheet on): replaying what was sent sends the same bytes, where
replaying the original would need the transform chosen again.

Copies out: ⌘C / Edit › Copy / right-click Copy (the selection is read from the
surface just before the emulator copies it; the clipboard is not read back), a
program's OSC 52 write once allowed, and the end of a drag when
`copy_on_select` is on. The same text again moves up instead of repeating.

**Never recorded**, each in one place:

- *A pasteboard carrying one of the three marks.* `TerminalPaste.clipboard`
  reads them with the content and returns `doNotRecord`; the flag rides the
  `Clipboard` value through the door, the sheet and every transform.
  `send(pasted:record:)` has no default for `record`, so a new caller cannot
  compile without deciding.
- *A private lane.* Not at a caller: `Ledger::record_clip` takes the pane id,
  joins to the lane and refuses `is_private`. It also refuses a pane it does
  not know, the opposite of `pane_is_private`'s answer for visits, because
  text whose lane cannot be checked is not known to be safe.
- *Blank text and anything over 64 KB* (`clips::admit`).
- *`paste_history = false` or `paste_history_keep = 0`*: nothing is written
  and the table is emptied, at launch, when the file is saved, and at the next
  paste.

**Text shaped like a secret is stored as its first four characters and `•••`**,
by `clips::redact`, inside the same function that writes the row, so the
original never reaches the file (a test greps the database and its WAL). The
whole entry, not the matching part. The shapes, each only at the start of a
word:

| shape | |
|---|---|
| `sk-` + 20 or more of `A-Za-z0-9_-` | OpenAI, Anthropic |
| `ghp_` `gho_` `ghu_` `ghs_` `ghr_` + 30 or more alphanumerics; `github_pat_` + 20 | GitHub |
| `AKIA` / `ASIA` + 16 of `A-Z0-9` | AWS access key id |
| `-----BEGIN …-----` | any PEM header |
| `eyJ….eyJ….…` | a JWT |
| `xox[abprs]-` + 10 or more | Slack |
| `glpat-` + 20 or more | GitLab |

Paste as Base64 of a source with one of these shapes is not recorded at all:
base64 has no shape. **This is a net, not a guarantee.** A password typed into
a note and copied without a manager looks like a word, and is kept for 30
days. `paste_history = false` is the answer for anyone that worries.

**The table** is `clip` (migration 0016): kind, content, redacted, the
original's line and byte counts, a timestamp. No pane or lane column: a row is
for getting text back, and one that named its lane would outlive it. Capped at
`paste_history_keep` (200) and `paste_history_days` (30) on every write and
read. Deleting one row and Clear Paste History run with `secure_delete` on, so
the freed pages are zeroed; no `VACUUM`. A strip export is built from lanes and
has no way to include it.

**The picker** is a `PaletteController` like ⌘P's. Newest first is the whole
ranking; typing filters by case-insensitive substring, every word required. No
index: it is 200 strings.

## Consequences

- An OSC 52 copy of a secret from a program (`pass -c` over ssh) is caught
  only by the net. Programs do not set pasteboard marks.
- A redacted row can be seen and deleted and nothing else; it is there so the
  list does not silently differ from memory.
- Copy-on-select is recorded from a mouse-up with a selection, not from the
  emulator's own write, which has no callback. A selection extended by
  keyboard is not seen. It is off by default.
- The WAL may hold a deleted row's bytes until the next checkpoint.
