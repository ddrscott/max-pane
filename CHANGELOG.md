## [Unreleased]

### Added
- Paste history, ⇧⌘H (Edit › Paste History…): what was pasted into and copied out of terminals, newest first, in a picker built on the ⌘P palette. ↩ pastes the row into the focused terminal (untidied, asked about when risky), ⌘C copies it back, ⌘⌫ (or ⌫ with nothing typed) deletes it after asking. **Never the system clipboard**: nothing polls `NSPasteboard`; a row exists only because a terminal pane sent those bytes or copied that text. Recorded at the one door every paste ends in, as the text that was sent (tidied text, quoted paths, a screenshot's path, a transform's output); a cancelled sheet and Paste File as Base64 record nothing. Copies out: ⌘C, OSC 52, and `copy_on_select` when on. Never kept: a pasteboard marked `org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType` (read with the content, carried as `doNotRecord`), anything in a private lane (refused in the ledger by pane id, not by callers), over 64 KB. Token shapes (`sk-`, `ghp_`/`github_pat_`, `AKIA`/`ASIA`, a PEM header, a JWT, `xoxb-`, `glpat-`) are stored as four characters and `•••`; a net, not a guarantee. Ledger table `clip` (migration 0016), capped by `paste_history_keep = 200` and `paste_history_days = 30`; `paste_history = false` records nothing and empties it. Edit › Clear Paste History… and a button in Settings delete every row (`secure_delete`). Not in a strip export. [ADR-0031](docs/decisions/0031-paste-history-is-what-terminals-pasted-and-copied-never-the-clipboard.md).
- Edit › Paste Special ▸, six rebindable commands live in a terminal pane. **Paste Escaped** (⌃⌘V): the clipboard as one shell word that runs nothing, by the path rule (bare, double quotes with `\ " $` and the backtick escaped, single quotes on `!`), a newline kept inside the quotes so the shell waits at `dquote>` and the confirm sheet is never needed; a tab, escape or other control character makes it `$'…'` with each written out. **Paste as Base64** (one line, never wrapped) and **Paste Base64-Decoded** (wrapped or unpadded is fine; not base64, or not UTF-8, is refused in one line). **Paste File as Base64…**: the files copied in Finder, else an open panel, as `base64 -d > "NAME" <<'EOF'` … `EOF` wrapped at 76 with no final Return, 5 MB at most, a delimiter checked against the body; the no-scp way onto a remote lane. **Paste Slowly**: ⌘V's bytes 16 at a time, 10 ms apart (`paste_slow_chunk`, `paste_slow_delay_ms`), a progress line in the pane, Esc (swallowed) or typing cancels and nothing of it is sent after; a marked stretch of the one `PacedInput` queue rather than a second queue. **Paste Without Asking** (⌥⌘V) moved into the submenu. ADR-0030
- Middle-click pastes in a terminal. The pane's own selection if it has one, read from the surface (`ghostty_surface_read_selection`) and never through a pasteboard, so the clipboard is untouched and `copy_on_select = false` loses nothing; otherwise the clipboard. Same door as ⌘V: tidied, asked about when risky, paced, remote lanes included, and the clicked pane takes the keyboard. A program with mouse reporting on (`ghostty_surface_mouse_captured`) keeps the click; ⌥- or ⇧-middle-click pastes anyway. A click on a URL or path pastes (opening is ⌘-click). Nothing in an unexpanded gallery tile. `middle_click_paste = true`, read at each click. **Found first:** a middle click was not unhandled. Ghostty's core answered it by pasting the clipboard itself, framed by its own guess at bracketed paste, the path `TerminalPaste` rules out; the pane now takes every middle click the program did not capture, so `middle_click_paste = false` means nothing happens rather than that.
- Pasted commands are tidied, and the pane says so. ⌘V of copied text (never a file's or a picture's path) straightens smart punctuation (`“ ” „ ‟` → `"`, `‘ ’ ‚ ‛` → `'`, `…` → `...`, non-breaking and other Unicode spaces → a space, zero-width characters removed except a joiner holding an emoji or Persian text together), removes a copied `$ `, `% ` or `# ` prompt when every non-empty line has the same one and what is left still reads as a command (never `> `), and trims leading blank lines and the end of each line, keeping indentation. A long dash that starts a word before a letter or digit is `--` (`—force` → `--force`, `git commit –amend`), any other is `-` (`a — b`, `–-flag`). Punctuation is only straightened outside clear prose: one line, or every line looks like a command, by a stated predicate (`TerminalPaste.looksLikeCommand`). The notice line reads `pasted · straightened 4 quotes · removed "$ "`; tidying happens before the decision to ask, and the sheet previews, sends and says `tidied: …`. ⌥⌘V pastes as copied, and `paste_tidy = false` (read at each paste) turns it off. No `as copied` undo on the notice: erasing a paste needs the far end to have echoed exactly the pasted bytes, and a highlighting shell or a TUI never does. `straightenPunctuation`, `stripPrompt`, `trimStray` and `tidy` are separate pure functions for the paste tasks that follow. ADR-0029
- OSC 52: a program in a terminal can set the clipboard, and must ask to read it. **Found first:** it did neither. pty-host lifts OSC 52 out of the output stream, so a tmux or nvim yank arrived as relay's `CLIPBOARD (0x16)` frame, which the client dropped without a word, in local and remote lanes alike; bytes that did reach Ghostty (an older pty-host) were written to the clipboard with nothing shown, and a read was denied with nobody asked. Now a program's copy lands on the clipboard (`osc52_write`, default `"allow"`; at most 1 MiB; an empty one never clears it) and the lane header says `COPIED` for two seconds, or the pane's notice line does when `BLOCKED` holds the chip. A read (`osc52_read`, default `"ask"`, every time) goes up as a sheet over the pane naming the program, the lane and the server the text would leave for, with what would be handed over; ↩ and Esc deny, and allowing takes ⌥A or a click, because a program raises this sheet and you may be typing under it. Both settings are read at each request. In a remote lane the relay web app's copies arrive by the same frame and obey the same setting. A read still cannot happen through a current pty-host, which eats the query. ADR-0028
- ⌘V of a screenshot pastes a path. When the clipboard holds a picture and neither files nor text (⇧⌃⌘4, a browser's Copy Image), it is written as a PNG and its quoted path is pasted: `~/Library/Caches/app.ljs.maxpane/paste/paste-YYYYMMDD-HHMMSS.png` (per profile, never overwriting, removed at launch after `paste_image_keep_days`, default 7), with `saved …, 1.2 MB` in the pane's notice line. Files still win over text, and text over a picture. **In a remote lane the picture is uploaded to the relay server** through its own `POST /api/upload`, the way the relay-tty web app does it, with the server's Keychain token, off the main thread; the path the server answers with is what is pasted, the pane says `uploading … to NAME…` meanwhile, and a failure is one line naming the server with nothing sent to the prompt. This is the first piece of remote Phase 4. `paste_image_max_mb` (25) refuses a bigger picture; `paste_images_as_files = false` turns it off. ADR-0027
- A risky paste asks first. With no bracketed paste (`TerminalPaste` says why there never will be), every newline inside a paste is the Return key, so a paste with a line ending inside it, a tab, or more than 16 KB is now held in a sheet over its pane before a byte goes: line and byte count, what is unusual in a line each, the first eight lines as they will be sent with control characters made visible. ↩ and Esc both cancel, because Return is the key the sheet exists to keep from being pressed by accident; **P** pastes, **O** pastes as one line (joined with a space, a trailing `\` continuation joined as the shell would), **T** toggles tabs to spaces. Nothing is remembered. **⌥⌘V, Edit › Paste Without Asking**, skips it once and is rebindable as `pasteWithoutAsking`. Settings `paste_confirm_multiline`, `paste_confirm_tabs`, `paste_confirm_bytes` (0 = never) and `paste_tab_width`, all read at each paste. The same in a remote lane. ADR-0026
- Everything a terminal pane sends leaves in pieces: at most 1 000 bytes a `DATA` message, cut on UTF-8 boundaries, one message per 5 ms, from the one queue keystrokes use, so typing during a long paste follows it and never lands inside it. No setting. A pty-host older than relay-tty 1.23 drops what its PTY cannot take in one write and a session keeps the pty-host it started with; against one built from the commit before that fix, unpaced pieces lost two thirds of 64 KB and 5 ms delivered 256 KB whole to a byte-at-a-time reader. 1 MB: 1 049 messages, 7.1 s local and 7.2 s through the relaytty.com tunnel, sha256 equal. A paste that will take a second or more says so in the pane's notice line. Input held while disconnected is flushed through the same pacer, and what is left of a paste when the wire goes is held or dropped whole by the existing rules
- Folding a sidebar group puts its lanes away. Collapsing a directory, a server's directory or a whole section (`// LOCAL`, `// NAME`, which now have a triangle; a click on the rest of a server's header still opens Settings › Servers) takes that group's lanes off the strip and out of the gallery, and opening it brings them back in the same order at the same widths. Nothing is closed, detached or written: the agents run on, terminals stay attached, pages stay loaded, and the memory policy treats a hidden page as a lane a long way off. A folded header reads `3 LANES HIDDEN` at rest with `1 BLOCKED` beside it in the blocked green, breathing, when an agent under it is waiting; the status bar reads `4 lanes · 3 hidden`; an empty strip that is empty because everything is folded says so. A terminal files under its session's directory and a web lane under its tag; a split lane in two groups goes only when both are folded; an untagged web lane and a docked lane never go. ⌘P, ⌘O's sessions, a sidebar row, `maxpane attach`, a click on `N ASKING` and a click on `N BLOCKED` in the status bar (new: it goes to the next blocked agent with a lane) open the group first and then you are there, and the lane with the keyboard is never hidden behind your back: if the terminal you are typing in does `cd` into a folded project, the project opens. Folding the group you are in hands the keyboard to the nearest lane still on the strip, right first. The lane you are in holds still while columns elsewhere on the strip close and open. The folds and the hidden lanes are in the ledger (`app_state`, no migration), so a relaunch comes back the same way, in its first frame. `sidebar_collapse_hides_lanes` (Settings › Lanes), on by default, applies live; off is the old behaviour exactly. See ADR-0024 and the README's "Folding a group puts its lanes away"
- Remote presence. A remote server that stops answering now says so at once, everywhere: its sidebar header carries a green outlined chip (`RECONNECTING`, `UNREACHABLE` after a minute, `TOKEN REFUSED`) with the last error as its tooltip; every session row under it goes to the at-rest grey with `—` and `OFFLINE` in place of a stale `working` or BLOCKED; the lane header shows the same chip where `BLOCKED`/`DONE` go; the pane's banner reads `RECONNECTING · INPUT IS NOT BEING SENT`; a gallery tile dims; the status bar says `N sessions · M offline` and a dead server's BLOCKED is no longer counted or bounced; `maxpane sessions` prints `offline`. The session list and the lanes now share one truth per server: the list gives up after 4 s (was 15), believes a failure only after one retry half a second later so a slow response never flaps, and pings `/ws/events` every 5 s — at most 13.5 s from a silent tunnel death to the sidebar, 10–12 s measured against the real server frozen with `kill -STOP`, under a second to recover — and when it goes quiet every lane on that server tests its own connection within 4 s instead of waiting out its 45 s zombie timer, while a lane that loses its connection makes the list check now; on recovery lanes re-attach at once. Typing into an offline lane is not queued for the length of an outage: the last 5 s before the connection returns is delivered, anything older is dropped, and the pane now says how many bytes in one line instead of only logging it. `maxpane server add` with a name that exists replaces that server's token. See ADR-0023 and the README's "Remote servers"
- The server chip. A remote session is marked by a small grey outlined square with its server's name (`WSL`), the same one component on its sidebar row, beside the path in its lane header and gallery tile, and on its ⌘O and ⌘P rows; ten characters then an ellipsis, tooltip the server's host, no colour per server. The displayed path stops repeating the server (`/home/spierce`, not `WSL:/home/spierce`; never `~` for this Mac's home) while the ledger's `host:path` tag is unchanged. The sidebar's servers are `// NAME` sections with their count and state chip, and this Mac gets a matching `// LOCAL` once a server is configured. With no `[[servers]]` nothing changes, pixel for pixel — the local render sheets are byte-identical before and after. ADR-0023 supersedes the "one mark is the name in the path" sentence of ADR-0020 and plan §0
- `maxpane sessions`, `maxpane attach [NAME:]ID` and `maxpane run @NAME COMMAND…`: the control socket reaches remote servers, so the app can be driven from a shell when nobody is at the screen. `maxpane ls` shows a remote lane as `pty:NAME:ID`, which is what `attach` takes back
- Remote relay-tty servers, Phase 3: start things there. With a remote lane focused, ⌘O `claude` ↩ starts Claude Code on that lane's server in that lane's directory, as a lane here, and it goes BLOCKED in the sidebar when it asks; ⌘T and ⌘D beside a remote lane start a shell on that server in that directory. A word at the front of ⌘O's field says where instead — `@yorkshire claude` runs on that server (its home, or the focused lane's directory when that lane is on it), `@local claude` on this Mac — and the row's second line says where before Return (`yorkshire:/home/spierce/proj`, `yorkshire:~`); a `@word` that names no server is left as typed and the row says so; the ⌘/ sheet lists the grammar. A directory over there is never this Mac's home: with none known, none is sent and the server answers with its own. Recents remember the server (as `host:path`, no migration) and a recent from a server that is not connected is not offered. The spawn is `POST /api/sessions` with the cookie, carrying the same no-`exec` wrapper a local session gets (`{"command": "$SHELL", "args": ["-li", "-c", "<line>\nexit $?"]}`; a bare shell is `$SHELL` with no args, which the server makes a login shell), because relay-tty's own spawn `exec`s the program and an exec'd agent is the session leader, which the classifier never calls BLOCKED; 201 is readiness and `GET /api/sessions/:id` follows. A refusal is one line naming the server and its error, with the picker back and the line still in the field. `maxpane run` from a local terminal still starts on this Mac. A remote project root is `server:` plus the session's directory itself — no git walk — so a remote project gathers with itself and never with a local path that matches. `RelaySessionSpawner` is now `LocalSpawner` behind the `SessionSpawning` seam, with `RemoteSpawner` beside it. With no `[[servers]]`, nothing changes. See ADR-0022 and the README's "Remote servers"
- Remote relay-tty servers, Phase 2: Settings › Servers. Paste the Auth URL a server printed at startup — the whole line, or a bare URL — into one field; the name defaults to the host's first label; the token goes to the macOS Keychain and the name and URL to `[[servers]]` in `config.toml`, comments kept; the server is asked at once and the row reads `connected · N sessions`, `refused` (with *paste the Auth URL from the server's startup output*), `no token`, `reconnecting` (with the host and why) or `disabled`, with a dot in the green family for a state and grey at rest. Buttons: on | off, paste token, remove (confirmed); the name is a field, so typing a new one renames the server and the ledger's panes and `host:path` tags follow it. Everything applies live — add, remove, enable, disable, rename, a pasted token, and a hand edit of the file through the config watch — with no relaunch: the registry gains or loses the server's source, the sidebar's group appears or goes, and a lane on a removed server stays put with a `SERVER NOT CONFIGURED` banner until the server is back. The sidebar shows each enabled server as its own header (name, state or session count, blocked count) above its project groups, a refused one as a header with no rows, a disabled one not at all; a click on the header opens Settings on that row. A 401 empties the server's list so ⌘O and the sidebar carry nothing from it. `maxpane server add` goes through the same door and applies live too. relay-tty 1.23.0 still authenticates the tunnelled WebSocket by cookie alone, so every relaytty.com row says so in one line. See ADR-0021 and the README's "Remote servers"
- Remote relay-tty servers, Phase 1: a session already running on another machine's relay-tty server appears in the sidebar and in ⌘O beside the local ones, grouped under `server:/path`, and attaches as an ordinary terminal lane over a WebSocket to that server — the same rendering, resize, replay, agent state and reconnect as a local session, surviving a relaunch. The one mark is the server's name where the directory sits: in the lane header, on the sidebar group, and before the id on a ⌘O row. Servers are `[[servers]]` tables in `config.toml` (`name`, `url`, `enabled`), hand-written or added with `maxpane server add NAME <startup auth URL>`, which keeps the token in the macOS Keychain against the server's host and never in the file; `maxpane server ls` says how each is doing. The sidebar group header carries `RECONNECTING` or `TOKEN REFUSED` ahead of its count when a server is not connected; a 401 stops the retrying. A reconnect that gets the whole scrollback where a delta was due (relay-tty's tunnel client drops a `RESUME` that races its bridge) replaces the screen instead of appending it, and a wake from sleep pings every remote connection at once. A pane's session is keyed on `(server, id)` throughout, the ledger gained `pane.relay_server` (migration 0015, NULL = local), and a remote lane's project is `host:path`, never a walk of this Mac's tree. ⌘-click on a path in a remote lane says in one line that it cannot open it yet; starting sessions remotely and a Settings section are the next phases. With no `[[servers]]`, nothing changes. See ADR-0020 and the README's "Remote servers"
- Maximize Pane. ⇧⌘↩ (View › Maximize Pane, iTerm's Maximize Active Pane) gives the focused pane the strip's whole visible window, and the same key — or the green `MAXIMIZED` chip on the row across its top — puts it back exactly where it was. The pane, not the lane: in a split lane its siblings keep their heights behind it. The sidebar, docks, toolbar and status bar stay where they are. Nothing is written and the lane does not widen: the pane's view is lifted over the strip and a placeholder holds its slot, so the lane's width, the `s | m | xl` switch and the strip's scroll offset are untouched and a relaunch comes back un-maximized. It eases out of the pane's rect on the strip's 0.22 s and back, at once under Reduce Motion. A page lays out at the new width and its full screen fills the maximized pane; a terminal gets the window's columns and the session hears one size going up and one coming down. A docked lane's pane fills the strip's window while its dock stays. Moving focus or changing the strip restores first (⌘[ ⌘], a new lane, ⌘W, a split, a dock, a resize, ⌘G); Esc never does. It works in the gallery as well, from a tile and from an expanded one, where it fills the whole gallery and goes back into the tile it came from. `keys` rebinds `toggleMaximizePane`. See ADR-0019
- The build carries Apple's passkeys capability when a provisioning profile grants it, and behaves exactly as before when none does. WebAuthn in a web pane needs `com.apple.developer.web-browser.public-key-credential`, a managed capability Apple grants per team and delivers as a provisioning profile; signed with the key and no profile the app is killed at launch, so the key is never in `MaxPane.entitlements`. `scripts/entitlements.sh` decides at signing time: the shipped file byte for byte with no profile, an ad-hoc signature, or a profile for another bundle id; the file plus the key and the profile's identifier entitlements when `packaging/MaxPane.provisionprofile` (or `MAXPANE_PROVISIONING_PROFILE`) grants it for this team and bundle, with the profile embedded; a hard stop for a profile that is present but ungranted, expired or another team's. `make-dmg.sh` refuses a bundle where the key and the embedded profile disagree, and `scripts/tests/entitlements.sh` pins every branch in the default test run. Passkeys themselves still do not work in a pane: the request to Apple, the profile and the webauthn.io proof need the Account Holder's account, and the README ("Passkeys and the provisioning profile") says exactly what to file and where to put the result
- Picture-in-picture in a web pane. WebKit keeps it off on macOS unless the embedder turns on a private preference — the public switch is iOS-only — so no site could offer it: the glyph was missing from the native controls, YouTube's and Vimeo's buttons said no, and `requestPictureInPicture()` rejected with `NotSupportedError`. Every pane's configuration now sets it the way WebKit's own MiniBrowser does, popups inherit it, and the call is guarded so a WebKit that drops the key leaves PiP off rather than crashing the app. A PiP window is the page's — destroying the web view closes it, measured — so eviction (ADR-0003) now leaves a pane alone while one of its videos is in PiP, and reclaims it once the video is back inline. `WebPictureInPictureTests` proves it on a real `<video>`; the one test that puts a PiP window on the display is behind `MAXPANE_PIP`
- Geolocation in a web pane. WebKit on macOS never answers `navigator.geolocation` — no denial, no timeout, a spinner forever — so the API is now a page-world script in every frame, built on WebKit's own `Geolocation` types, and the pane answers it: the first call from a site asks in the pane's sheet (`WANTS TO KNOW WHERE YOU ARE`), once per site per cookie jar, remembered in the ledger like a camera grant, and two calls during one sheet are one sheet. Only a yes reaches CoreLocation, where macOS asks about the app itself the first time; a no from you or from System Settings is `PERMISSION_DENIED` at once, and Esc is *not now*. One location manager serves every lane, `watchPosition` hears every fix, `maximumAge` is honoured from the last one, and `timeout` runs from the yes. `NSLocationUsageDescription` and the hardened-runtime location entitlement are in the bundle
- Private web lanes. ⇧⌘N (File › New Private Web Lane) opens a lane on a blank page with the cursor in the address, marked `PRIVATE` on its header, its chrome bar and its ⌘P rows. Its pages live in a `WKWebsiteDataStore` that is never written to disk and is dropped when the lane closes; no visit reaches history, no title correction, no session blob, and ⇧⌘L is greyed out while ⌥⌘L still fills. A ⌘-click from a private page opens the sibling lane in the same private store, signed in. A relaunch never brings a private lane back: the ledger deletes it at open, and a `kill -9` with the lane up is the same case. See ADR-0016
- Pinch to zoom in a web pane. A trackpad pinch drives the same persisted page zoom as ⌘= and ⌘-, reflowing the page live, and settles on the nearest rung of the zoom ladder when the fingers lift (eased on the pane's 0.16 s, at once under Reduce Motion), so it survives a relaunch and ⌘0 resets it. A two-finger double tap goes to 150% from actual size and back to 100%. A popup's page gets WebKit's own transient pinch. `upgradeKnownHostsToHTTPS` is set explicitly on every pane's configuration, and a test pins both
- Print, and Save as PDF, for a web pane. ⌃⌘P (File › Print…) runs the system print panel as a sheet over the pane, fitted to the paper's width, with the panel's own Save as PDF in its PDF menu; a popup's page prints from inside the popup. File › Save as PDF… writes the whole page — every fold, not the one on screen — to a file chosen in a save panel named after the page, and the result lands as a finished row in the pane's download bar. Both are greyed out on a terminal lane. ⌃⌘P rather than ⌘P because ⌘P is the palette; `keys` moves it and binds `savePDF`
- Web notifications. WebKit has no `window.Notification` on macOS, so Slack, Gmail and every chat app in a pane could neither ask nor notify; now the API is a page-world script in every frame, and the pane is the centre behind it. `requestPermission()` asks in the pane's own sheet, once per site per cookie jar, remembered in the ledger like a camera grant; `Notification.permission` reads the remembered answer before the page runs. A granted `new Notification()` posts through macOS's Notification Center with the site's title, body and icon, and a click brings the app, the lane and the pane forward and fires the page's `click`. Nothing is posted for the pane you are looking at. macOS is asked for permission the first time a site is allowed, not at launch. Only a live page can notify — an evicted pane's cannot — and a service worker's `showNotification` is not supported
- Ad and tracker blocking in every web pane and the popups over them, with WebKit's own content blocker. The rule list is fetched from `blocking_list_url` (default: Adblock Plus's WebKit-format conversion of EasyList; several URLs are joined), compiled once into the profile's rule-list store, looked up from there on later launches and refreshed daily; a list past WebKit's 150 000-rule ceiling is cut into several with the exception rules in every part. Off for one site from the lane's ⋯ menu or Navigate › Block Ads on This Site, by registrable domain, kept in the ledger; the chrome bar wears an `unblocked` chip on such a site, and a click on it turns blocking back on. `blocking = false` turns it off everywhere; `keys` binds `toggleBlocking`
- Web Inspector on every web pane: right-click, Inspect Element, or attach from Safari's Develop menu. Always on, since the app is for people who build pages

### Changed
- A server has a colour, and the sidebar row's grey name chip became a colour square. Each remote server is known by one of eight colours (`slate`, `cyan`, `blue`, `violet`, `magenta`, `rose`, `lemon`, `ink`; `color = "violet"` on its `[[servers]]` table), and a small solid square in that colour is the mark: on every sidebar row under `// WSL`, where the grey `WSL` chip used to be, with the name as its tooltip, because the section already names the server. The header's `//` takes the colour. The name chip stays where nothing else names the server — the lane header and gallery tile, ⌘O and ⌘P rows — outlined and lettered in the colour, and becomes the square alone on a tile too small to read or a header too narrow. Offline, the square goes hollow in the same colour and the chip dims. Pick it from a right-click on the server's sidebar header (**Color ▸**, with **Rename…**, **Disable** and **Server Settings…** beside it, all through Settings' own code), from the swatches on its row in Settings › Servers, or with `maxpane server color NAME COLOR`; `maxpane server ls` gained a colour column between the URL and the state. A new server gets the first colour nobody is using, and a table written before colours existed gets one on first load, written once. Changes apply live and cross-fade. State is still green and DONE still orange: the colours are identity, each at least ΔE 40 from every green and from DONE (the suggested `amber` and `teal` failed that and were replaced by `lemon` and `ink`), and nothing local changes — the local render sheets are byte-identical. ADR-0025 amends ADR-0023 and carves the exception out of ADR-0015
- ⌘G is a motion in both directions instead of a cut. Going in, every tile eases out of the place its lane had on the strip; coming out, every lane eases out of its tile, and lanes bound for beyond the window slide out through its edge. A lane that was off screen comes in from that side, from just past the edge rather than from its true distance. The strip's 0.22 s and ease-out, no lane resized for the effect, and nothing under Reduce Motion. See ADR-0011's amendment
- Only the terminal with the keyboard blinks its cursor. Every terminal used to, and in the gallery that was a dozen cursors out of phase. The cause was a surface's state at birth: Ghostty's surfaces start out believing they are focused, and the library tells one otherwise only when its view gains or loses first responder, so a terminal that had never held the keyboard (each restored lane, each gallery tile) was never told and blinked as the focused one does. Each pane now tells its surface the truth when the surface is built, when its view enters a window, and after every focus report: focused means first responder in the key window, so nothing blinks with the keyboard in a web pane, a find bar or ⌘O, or with another window or app in front. The rest show Ghostty's still, hollow cursor. It is the `cursor_blink` setting (Settings › Terminals & sessions): `"focused"` by default, `"never"` holds every cursor still, `"always"` blinks them all as before. Applies on the next launch, like the font. Tests ask real surfaces what they believe, through focus reporting (`CSI ? 1004 h`)
- Selecting text in a terminal no longer copies it. `copy-on-select` had been hard-coded on since the libghostty migration, so every accidental highlight silently replaced whatever had been copied on purpose. It is now the `copy_on_select` setting (Settings › Terminals & sessions), **off by default**; ⌘C, Edit › Copy and the right-click Copy item copy the selection as before. Set `copy_on_select = true` to get the old behaviour back. Applies on the next launch, like the font. A test on a real surface and the real pasteboard pins both states
- An expanded gallery tile's seams drag. The separator between two stacked panes in the expanded tile resizes them exactly as on the strip — same arithmetic, same grab band, one ledger write on the drop, and the terminals hear the same live-resize word — so leaving the gallery shows the panes where the drag left them, and a relaunch keeps them. The pane grips come back on the expanded tile too. Unexpanded tiles are as handle-free as before, and their seams now let the click through and never show a resize cursor over a seam that will not move. A tile clamped below half size keeps its handles hidden. ADR-0011 amended

### Fixed
- ⌘V of a file copied in Finder pasted only its name. Finder writes each file as a file URL *and* a string flavour holding the display name, and the terminal's paste read the string. File URLs now win: the paste is the full path (absolute, not `~`-abbreviated, not percent-encoded, a `/.file/id=…` reference resolved, nothing stat'ed), several files space-separated in order, no trailing space or newline. A path is quoted only when it needs it, in double quotes with `\` `"` `$` and the backtick escaped; a path with `!` gets single quotes instead, because history expansion is live inside double quotes; a file whose name holds a newline or other control character is left out and the pane says which in one line. Dropping files from Finder on a terminal pane types the same quoted paths at the cursor and focuses the pane. In a remote lane the path is this Mac's, pasted unchanged. `TerminalPaste.shellWord(for:)` is the quoting and `TerminalPaste.clipboard(_:)` the one place a paste reads a pasteboard. See the README's "Pasting into a terminal"
- A session started on a remote server never became a lane. The remote spawner held itself weakly in its network callback, and every caller makes one for a single spawn and lets it go, so by the time the server answered it was gone and the completion was never called: a session running on the box, no lane here, no error. ⌘O, ⌘T and ⌘D beside a remote lane all went through it. Found by driving the installed app over its control socket with the screen locked; the tests had each held their spawner in a `let`. The request now holds the spawner until it answers, and a test spawns through a temporary
- Save as PDF… has a deadline. Neither the page-height measurement nor `createPDF` is promised a completion — asked of a page mid-navigation, or whose content process goes away, WebKit drops it — and the pane was waiting on it forever: no row, no error, nothing to click. The render now runs under a 30 s deadline and a miss is a failed row in the download bar with the reason (`the page did not render as PDF within 30 s`). The same hang stuck `./scripts/test.sh` in about half of runs, because the `WebPrintTests` failure test asked for the PDF before its page had started loading (`isLoading == false` is true before `load` begins); it now waits for the page by title and fails the write against a regular file in the path rather than a missing directory, which is a failure on every filesystem
- `scripts/test.sh` forces `MAXPANE_PROFILE=tests` and unsets the four path overrides (`MAXPANE_SOCKET`, `MAXPANE_LEDGER`, `MAXPANE_CONFIG`, `MAXPANE_DATA_SALT`) instead of defaulting the profile. A shell inside a live Max Pane pane inherits `MAXPANE_PROFILE=default` and the app's socket, so a run from there saw the empty default salt, every real-WebKit suite printed `SKIPPED`, and the run went green having proved less than it said. The default run now ends with a count of the real-WebKit suites in the tree, how many ran, which were opted out by `--skip` (now passed through to `swift test`), and how many the profile guard skipped; any of the last fails the run

## [0.6.0] - 2026-09-16

### Added
- DONE: a session that finishes a turn is marked DONE in the sidebar, on its lane header and in ⌘P, until you focus its pane or `doneHoldSeconds` (30 min) runs out. relay-tty's own DONE only exists while nothing is attached, so it never showed for a lane
- The Dock icon bounces once when a session becomes DONE or BLOCKED while the app is in the background
- Mobile Layout, in a lane's ⋯ menu and the View menu: the lane's pages ask their sites for the phone layout with an iPhone user agent and reload. Per pane, kept in the ledger, off by default; `keys` binds `toggleMobileLayout`
- A notarized DMG and a Homebrew cask — the app signs with hardened runtime and `scripts/make-dmg.sh` staples Apple's ticket, so a download opens with no Gatekeeper warning. Apple silicon, macOS 14 or newer

### Changed
- Opening a lane with no relay-tty installed says what to install and how, instead of naming a config key
- Sidebar colour marks a change of state only: grey at rest, green working, Signal Orange done, BLOCKED as before. The WORKING chip is gone; the green mark and the rate carry it

### Fixed
- A lane centred in the carousel lost its `s | m | xl` switch and `⋯` menu to clicks: the end-lane margins were scroll-view content insets, which AppKit covers with an invisible view that takes the press. The margins are document padding now

## [0.5.0] - 2026-09-15

### Added
- Lanes: terminals and web pages as peer panes, in portrait columns on an infinite horizontal strip
- Gallery layout — every lane on one screen, live, switched with two icons in the toolbar
- Lane size presets s | m | xl in every lane's menu, docks included; ⌘\ cycles them
- Drag a lane by its header onto any edge of a pane, on the strip and in the gallery
- Pick a pane up and drop it in another column
- ⌘D splits any pane to the right, the way iTerm does
- Carousel: the focused lane centres when fewer than three lanes fit, first and last lanes included
- One lane per agent session, with a session sidebar that reveals and focuses the lane
- Web panes with address-bar completion and a find bar that counts matches
- A page's popup opens as a dialog over the window, never as a new lane
- A page's full screen fills its pane; ⇧ or a second request takes the whole display
- Kept pages: the ★ in a page's chrome bar keeps it, on a bookmark bar you can reorder; Keep This Page is in the Navigate menu and bindable through `keys`
- History with no limit, in a window with room for it; another browser's history imports interleaved by date
- Passwords live in the Keychain and go nowhere else
- ⌘-click a file path in a terminal to open it in your editor
- ⌘O runs a command line rather than pretending to be a shell
- Keymap as a config file, with Esc doing something at last
- Every setting editable in Settings, stored as comment-preserving TOML
- Follows the system light/dark mode live, with a theme override
- Lucide icons across the chrome, and a globe on web rows
- One green family for status; BLOCKED is the brightest green and pulses slowly
- Panes never inherit Claude session markers from the process that launched the app, so `claude` inside a pane saves its transcript
- The core is linked statically, so a rebuild in the checkout cannot break the installed app
